# WP-01: детерминированные данные и чтение ресурсов

## Why

FR-04 и FR-11 требуют чтения занятия и группы по идентификатору. NFR-02 требует
воспроизводимой схемы Alembic, NFR-03 — фиксированного seed и сброса без изменения Clock.
Без этого последующие пакеты и e2e не имеют устойчивого исходного состояния.

## What Changes

- Добавляются ORM-модели Group и Lesson, заполняется исходная ревизия 0001.
- Добавляются ограничения БД для части BR-01/BR-02 и структуры переноса.
- Реализуются load_seed, SEED_ON_START и POST /__test/reset.
- Seed при старте переносится из docker/entrypoint.sh в lifespan без двойного запуска.
- Реализуются GET /groups/{group_id} (FR-11) и GET /lessons/{lesson_id} (FR-04).
- Добавляются изолированные API-тесты и отдельные проверки PostgreSQL 16.

## Capabilities

### New Capabilities

- `catalog-bootstrap`: схема, seed/reset и чтение ресурсов по нормативному контракту.

### Modified Capabilities

Нет: предметных спецификаций в исходном openspec/specs пока нет.

## Impact

Изменяются src/app, migrations и README. Нормативные openapi.yaml и asyncapi.yaml
не меняются. Новые зависимости не добавляются. Публикация событий и people-stub
в этом пакете не используются.

## Trade-offs and Alternatives

- PostgreSQL INSERT ON CONFLICT (id) DO NOTHING сохраняет изменения существующих
  записей. UPSERT с обновлением отвергнут: повторный just seed не должен отменять
  пользовательские изменения; восстановление эталона выполняет только reset.
- TRUNCATE двух таблиц в одной транзакции выбран для полного тестового сброса.
  CASCADE отвергнут, чтобы случайно не очищать чужие таблицы.
- VARCHAR с CHECK для перечислений проще откатывать, чем PostgreSQL native enum.
- Заполняется именно исходная 0001 по условию WP-01. Для уже применённой пустой
  0001 требуется явно вернуть версию пустой БД к base перед upgrade; для развёрнутого
  сервиса в эксплуатации вместо изменения применённой миграции нужна новая ревизия.
