# WP-04: список и частичное изменение занятий

## Why

FR-03 требует фильтруемого детерминированного списка; FR-05 — PATCH только в
PLANNED, с повторной проверкой BR-01..BR-07 и защитой от конкурентных обновлений.

## What Changes

- Добавляются фильтры, total/items и пагинация GET /lessons.
- Добавляется PATCH с различением пропущенного поля и явного classroom_id:null.
- Значения PATCH и ранние BR проверяются после статуса, до people-stub.
- Advisory locks расширены на объединение старых/новых ресурсов; строка читается FOR UPDATE.
- Устаревший снимок приводит к повторному слиянию с текущим состоянием, без потери полей.
- Добавлены unit/API/PG-тесты, включая неизменённую публичную функцию E2E-02.

## Capabilities

### New Capabilities

- `lesson-browsing-and-editing`: просмотр расписания и безопасный частичный PATCH.

### Modified Capabilities

Нет: создание, validate, seed, Clock и клиент предыдущих пакетов сохраняются.
Общий helper блокировок обратно совместимо принимает несколько снимков ресурсов.

## Impact

Расширяются API, LessonService и scheduling repository; добавляются чистые
LessonFilters и listing repository. Обновляется README. Контракты YAML, ORM,
миграции, зависимости, main/context, broker/jobs не меняются.

## Trade-offs and Alternatives

- model_fields_set/exclude_unset вместо exclude_none: иначе нельзя очистить аудиторию.
- Проверка значений PATCH отложена до чтения статуса: невалидный интервал не должен
  скрывать LESSON_NOT_EDITABLE. Форма JSON проверяется при входе.
- Сравнение полного DraftLesson вместо updated_at как версии: Clock может быть
  заморожен, и несколько обновлений получают одно время.
- Повтор транзакции при устаревшем снимке вместо добавления новых locks вне порядка:
  повтор освобождает все locks до нового HTTP и не перезаписывает чужие изменения.
- Для списка REPEATABLE READ обеспечивает один снимок total/items; запись сохраняет
  READ COMMITTED. Один общий уровень изоляции для чтения и записи отвергнут.
