# Зачем

FR-14 (Should) добавляет POST /lesson-series: до 50 занятий по UTC-дням недели,
общая принадлежность к серии и атомарная проверка BR-01..BR-07.

# Что меняется

- Чистые SeriesPlan/Weekday и генератор UTC-дат в domain/series.py.
- Nullable UUID series_id у Lesson/ответа/seed DTO, additive Alembic revision 0002.
- Один общий people lookup через прежний gather 3/2, затем упорядоченный assess
  под ресурсными locks и FOR SHARE группы.
- Flush каждого проверенного занятия в той же транзакции: следующие проверки
  учитывают предыдущие экземпляры, включая BR-06. Hard error содержит occurrence_index.
- При успехе 201 LessonSeriesResult; ни создание серии, ни отказ не отправляют события.
- Одиночные/seed занятия возвращают series_id=null. PATCH сохраняет series_id;
  reschedule переносит принадлежность исходного в нового преемника.

# Trade-offs и альтернативы

Выбрана nullable колонка без отдельной таблицы series: у серии нет собственной
статусной машины или метаданных по контракту. Индекс помогает находить её участников.
Отдельный commit на экземпляр отвергнут: он нарушает «всё или ничего».
Проверки экземпляров последовательны по индексу, как требует запрос WP-08;
один AsyncSession не используется одновременно несколькими корутинами.
Конкурентность общих внешних проверок ограничена одним batch из 3/2 запросов,
вместо count одинаковых batch. Это трактовка bounded concurrent validation из TASK §4
для общих ресурсов серии; дополнительный искусственный async fan-out не добавлен.

# Влияние

Контракт openapi.yaml уже содержит FR-14 и optional series_id, его менять не нужно.
0001, Clock, readiness, broker/events и конфигурация сохраняются. Два старых
ожидания чтения seed обновляются только на дополнительное series_id=null.
